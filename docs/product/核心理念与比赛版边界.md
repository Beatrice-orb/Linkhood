# 搭把手｜Project Brief

> 版本：v0.3
> 日期：2026-07-11
> 状态：产品名称与核心理念已拍板；具体 Demo 模块、AI Agent 形态和互助信任机制仍在收敛。

## 一句话定位

**搭把手是以社区为入口的公共服务连接与运营协作平台：把散落在社区、街镇、政府部门、公共机构、企事业单位和社会组织中的服务，转成居民找得到、看得懂、能行动、可追踪的身边服务；对正式服务覆盖不到的低风险生活小事，再由经过社区身份核验的邻里彼此搭把手。**

> **让公共服务更容易抵达居民，让邻里在可信、低风险的场景下彼此搭把手。**

## “搭把手”的双重含义

1. **公共服务为居民搭把手**：社区、街镇、政府部门、公共机构、企事业单位和社会组织提供的服务，通过统一入口更有效地抵达居民。
2. **邻里彼此搭把手**：借工具、非贵重物品代取、旧物赠送 / 交换、公共区域临时搬抬等低风险生活小事，由经过社区身份核验的邻里协作完成。

AI 是帮助供给方和社工减负的能力层，不替代这两个品牌核心。

## 要解决的根问题

西红门及大兴并不缺公共服务，缺的是“供给到居民”的连接与行动层：

- 信息散落在社区通知、公众号、政府网站、海报、附件和群消息里。
- 居民很难快速判断服务对象、资格、地点、状态、报名方式和下一步。
- 社区知道自己发过什么，却缺少跨来源的供给视图，也很难看见居民搜索了什么、哪里长期缺供给。
- 微信群擅长传播，传统社区系统擅长内部登记和台账，但都不天然完成“结构化供给—居民行动—状态反馈—供给优化”的闭环。

## 产品价值闭环

**供给聚合 → 信息结构化 → 居民发现与行动 → 状态与反馈回流 → 脱敏需求趋势 → 社区优化供给。**

邻里互助只承接正式公共服务无需或无法覆盖的低风险长尾小事，不另造陌生人社交广场。

## 两端价值

### 居民端

- 一个入口找到社区、街镇和区级的公共服务、活动、场所与社工对接。
- 清楚看到服务来源、适用人群、资格、时间、地点、状态与下一步。
- 围绕真实需求完成报名、预约、收藏、咨询或转介。
- 正式服务无法承接时，再进入低风险邻里互助。
- 社交不是目的；轻连接来自一次次真实、可完成的服务与协作。

### 社区 / 社工端

- 不是复制社区云的 CRUD、登记和静态台账，而是补充面向真实服务与活动的运营协作层。
- 聚合多部门、多机构供给，提高活动、场所、志愿者和社会组织资源的触达与利用率。
- 看见服务从曝光、收藏、报名到到场 / 完成的过程，并发现未满足需求与供给缺口。
- 以脱敏聚合数据辅助供给决策；专业个案记录与普通用户数据隔离。
- 通过 AI 减少供给录入、活动运营、通知整理、报表汇总和记录草稿等重复劳动。

## 与现有产品的差异

- **微信 / 朋友圈**解决传播与熟人关系；搭把手从具体需求出发，补齐来源、资格、状态、行动和完成闭环。
- **传统政务 / 社区系统**更重内部流程、登记、处置与汇报；搭把手补上跨供给方协同、居民互动、服务运营和反馈优化。
- **普通邻里社交产品**先建广场再等待社交；搭把手让居民因真实服务或互助产生连接，在可信协作中形成邻里关系。
- **社区生活地图**是居民端很有价值的发现入口，但不是产品总定义；地图之上必须有真实供给、状态和行动。

“5 公里”代表身边可达的排序偏好，不是硬边界；区级稀缺服务可能超过五公里。

## AI 的当前定位

已确认的原则：

- AI 负责识别来源、抽取字段、提示缺项、匹配需求、生成运营草稿、聚类脱敏需求。
- 每个答案带来源；每个关键发布、状态确认、个案入档和处置动作由人确认。
- AI 不自动确认余量、分配稀缺名额、替机构承诺、给居民打信用分或依据敏感数据做邻里匹配。

候选能力而非已拍板 Agent：

1. 供给接入：文章 / 海报 → 结构化服务卡 → 缺失字段 → 社工确认。
2. 活动运营：活动方案、报名表、提醒、总结与复盘草稿。
3. 居民问答与分流：基于核验来源回答并决定服务、转介、人工或低风险互助。
4. 社工记录：经授权的走访 / 个案记录草稿，人工确认后进入隔离系统。
5. 需求洞察：只对脱敏聚合信号做趋势和供给缺口分析。

比赛版只选 1 条主链路演通，其余进入路线图。

## 数据、信任与安全边界

- 公共供给数据保留来源、对象、资格、状态、核验时间和缺失字段。
- 居民的偏好、收藏和参与记录由本人可见、可修改、可撤回。
- 社区需求趋势只使用脱敏聚合数据。
- 专业社工个案记录与普通产品档案隔离，按授权和最小必要原则访问。
- 不把参与次数、互助次数或社交活跃度自动变成居民信用分。
- 公共服务可开放浏览；邻里互助需要社区身份核验，并以低风险白名单、平台内沟通、举报和双方完成确认为基础。
- 首版不承接进家门照护、借贷、贵重物品、医疗急救、儿童 / 老人单独照看等高风险场景。

## 黑客松最小证明

> 西红门真实公共服务已经很多，但散落在公众号、海报和政府网站里。搭把手用 AI 把一篇真实通知变成带来源、资格、状态和行动入口的服务卡；居民快速找到并参与，社区看到居民在找什么、哪里缺服务，再优化触达和供给。正式服务之外的一件借工具小事，则由可信邻里完成。

成功标准：

1. 至少 3 张真实西红门 / 大兴服务卡进入居民端，而不是只展示商家和虚构活动。
2. 至少 1 条“原文 → AI 草稿 → 社工确认 → 居民行动 → 脱敏需求反馈”的闭环可演示。
3. 邻里互助只演示 1 个低风险场景，并明确身份与安全边界。
4. 所有真实供给有来源、状态与最后核验时间；模拟数据明确标注为模拟。
5. 评委能够分辨：地图是入口、公共服务连接是主价值、AI 是运营杠杆、邻里互助是可信补位。

## 已确认、当前判断与待定

### 已确认

- 名称：搭把手。
- 双重核心：公共服务为居民搭把手；邻里在低风险场景彼此搭把手。
- 面向居民与社区 / 社工的双边产品，不再以空巢青年、兴趣搭子或青年公寓为总定位。
- 真实供给优先；AI 草稿、人工确认。

### 当前判断

- 公共服务连接层是比赛主故事，邻里互助用一张侧卡补足品牌含义。
- 社区生活地图值得保留，但降为居民发现入口。
- 积分、信用分、实时群聊和复杂社交关系不应成为比赛版主线。

### 待定

- 居民端最终导航与屏数。
- 首个共建 owner：镇、社区、医院、社会组织或其他公共服务机构。
- 邻里身份核验粒度：社区、小区或楼栋。
- 比赛版具体 AI 形态与部署方式。
