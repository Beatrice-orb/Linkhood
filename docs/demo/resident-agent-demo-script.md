# 居民社区生活助理 Agent｜90 秒两轮演示脚本

> 演示目标：证明 Agent 不只是按关键词回复公告，而是能理解居民口语里的生活目标和隐含约束，组合本地社区知识，经过一次追问给出更匹配的行动建议，并在第二轮结尾提供白名单模拟科室电话。
>
> 全部服务、活动、地点、来源、科室和电话均为演示数据。
>
> 本版本只沉淀聚合需求标签，不创建留言、工单或匿名需求信号，也不连接 ToG 留言板。

## 1. 演示前准备

- ToC 来源：`main@6e5bf2b`；居民原版 Portal 的内部页面、模式与交互保持完整。
- ToG 来源：`main@dc2dd601ce02ec794b11b648924fd82efcd03525`；通过 iframe 隔离展示完整上游 UI。
- 打开固定 Preview 域名，默认进入居民端；同一网页只保留一个很小的“居民端 / 社区端”切换，不展示旧五端首屏或大型 Launchpad。
- 居民端视口约 390×844，社区电脑端约 1440×900。
- 居民端只在右下角显示小助手形象，点击后展开对话，不压缩或替换 Portal 主体。
- 确认本地小知识库加载成功；所有模拟回答显示来源和核验时间。
- 真模型不可用时，确定性回退也必须完成相同的两轮建议。

## 2. 本地 API Key 内存配置

本地开发可以提供“模型设置”入口，但必须满足：

1. 仅允许在 `localhost` 开发环境出现；固定 Vercel Preview 不提供个人 Key 输入框。
2. Key 通过同源本地接口交给本地服务进程，只存在于该进程内存；页面输入提交后立即清空。
3. 不写入 `localStorage`、`sessionStorage`、Cookie、URL、日志、埋点、错误信息、项目文件或 Git 历史。
4. 页面只显示“本次本地会话已配置”及模型名，不回显完整 Key；停止本地服务后配置失效。
5. Preview 使用部署平台服务端环境变量，不把 Key 下发到浏览器。
6. 无 Key、Key 无效、超时或返回结构异常时自动使用确定性回退，不在居民界面暴露供应商错误。

演示前应使用新建的临时测试 Key；任何曾在聊天、截图或文档中明文出现的 Key 都应先撤销，不得继续使用。

## 3. 主场景：陪家人安心学会手机办事

### 0–10 秒｜打开生活助理

画面：保持 ToC 原版居民主页和交互，点击右下角助手形象。

旁白：

> 居民不用先理解社区组织结构，只要用日常语言说出正在遇到的事情。Agent 会在已发布服务里理解、筛选和解释。

### 10–35 秒｜第一轮：从口语理解真实任务

居民输入：

> 我妈刚搬来这边，手机就会接电话。我白天上班，她想学会自己挂号、交水电费，但那种大课她肯定跟不上。社区有没有人能慢慢教？最好别跑太远。

预期回答：

> 我理解你找的不是一节泛泛讲功能的“手机课”，而是有人围着“挂号、缴费”这两个具体任务，陪她一步一步练。
>
> 当前演示资料里，更匹配的是党群服务中心一层的「数字生活帮办桌」：每周二、周四 14:00—16:00，采用一对一短时陪练，可以练医院小程序挂号、水电缴费页面怎么找、乘车码怎么打开。它不是大班讲座，第一次去可以只带自己的手机，再把最想学的两件事写在纸上，工作人员会按实际任务慢慢讲。
>
> 地点从社区南门步行约 6 分钟，一层可直接进入。帮办人员只做操作引导，不代替居民付款，也不会索要或保存支付密码、短信验证码。
>
> 来源：社区数字生活服务演示清单，2026-07-12 核验。以上均为演示数据。

画面要点：

- 回答说明真正理解到的目标，不只返回一个活动标题。
- 同时组合服务形式、支持任务、距离和隐私规则。
- 第一轮不急着给电话，不采集联系方式。

### 35–65 秒｜第二轮：继承约束并调整建议

居民追问：

> 她下午一两点一般要休息，我也不太放心她自己弄付款的东西。我只有周六上午能陪她，那是不是就没合适的了？

预期回答：

> 不是没有，更合适的选择需要从工作日帮办桌换成周六专场。
>
> 当前演示安排里，7 月 25 日周六 09:30 有一场「手机安心用小课堂」，前 40 分钟会用演示页面讲挂号和生活缴费，10:20 以后留有一对一练习时间。你可以陪她先把两个任务各操作一次，再让她照着纸质步骤卡自己重做一遍，这比直接参加工作日下午的帮办桌更符合你们的时间。
>
> 关于付款安全，居民始终自己拿手机，工作人员只指步骤，不查看支付密码或短信验证码；涉及付款时可以练到确认页，最后一步不必真的支付。当前资料没有实时名额信息，请先确认当周场次。
>
> 可联系社区民生服务岗：010-0000-1001，工作日 09:00—18:00（模拟号码，不可拨打）。
>
> 来源：社区数字生活服务演示清单、社区服务联系目录，2026-07-12 核验。以上均为演示数据。

画面要点：

- 继承首轮“挂号、缴费、慢节奏、距离近”等目标，再叠加周六上午和隐私顾虑。
- 清楚解释为什么换推荐，不假装工作日下午的供给仍然合适。
- 电话只来自白名单，并放在第二轮回答结尾。

### 65–80 秒｜展示需求洞察边界

### 80–90 秒｜收口

旁白：

> 这个助理的价值不是替社区受理事项，而是把散落的服务信息转成居民真正能使用的建议，同时用脱敏聚合标签帮助运营人员理解需求结构。

## 4. 备选场景：新住民低压力认识邻居

第一轮输入：

> 我搬来快两个月了，周末还是一个人都不认识。想参加点社区活动，但我最怕一上来就轮流自我介绍，也不想一报名就连上十节课，有没有松一点的？

第一轮预期回答：

> 你想找的重点不是“学一门课”，而是能一个人去、参与压力低、随时结束，同时自然认识几个人的活动。
>
> 当前演示资料里，「邻里交换桌」比连续课程更合适：每周日下午在党群服务中心庭院开放 45 分钟，不要求连续报名，也没有上台自我介绍。可以带一本看完的书或一件闲置小物，也可以空手参加；主持人会用物品和社区地图做聊天引子，一个人去也会有人协助加入小组。
>
> 如果第一次只想看看，可以先参加前 20 分钟，不需要承诺后续场次。
>
> 来源：社区邻里活动演示目录，2026-07-12 核验。以上均为演示数据。

第二轮输入：

> 我周日上午有事，下午四点以后才行。一个人过去会不会大家都已经认识，反而更尴尬？

第二轮预期回答：

> 这个时间正好能匹配周日 16:30 的场次，而且它专门保留了“第一次参加”入口：新参加的人会先拿一张社区地图任务卡，由主持人安排两三人一起完成，不需要自己找话题，也不会默认大家已经认识。
>
> 建议你 16:25 到，在入口直接说“第一次来，想参加地图任务”即可；活动约 45 分钟，中途离开也没有影响。当前资料没有实时人数信息。
>
> 如需确认本周是否照常开展，可联系社区活动运营岗：010-0000-1024，工作日 09:00—18:00（模拟号码，不可拨打）。
>
> 来源：社区邻里活动演示目录、社区服务联系目录，2026-07-12 核验。以上均为演示数据。

备选洞察标签只允许包含：`local_social_connection`、`low_commitment`、`solo_attendance`、`no_public_introduction`、`sunday_late_afternoon`、`facilitated_entry`。不得把“怕尴尬”推断成焦虑或心理状态。

## 5. 演示检查

- 同一网页默认进入居民端，只用一个很小的“居民端 / 社区端”切换；不显示旧五端首屏或大型 Launchpad。
- ToC 原版 Portal 的既有页面、模式、主导航与内容完整保留，没有因助手而被压缩。
- 右下角只显示助手小形象；点击后展开，关闭后不遮挡底部导航。
- 两轮都由自由文本输入触发，不依赖词卡才能运行。
- 第二轮确实继承第一轮目标与约束，回答中说明推荐理由。
- 来源、核验时间、未知项和“演示数据”清晰可见。
- 电话只来自白名单，第二轮结尾注明模拟号码不可拨打。
- 居民端没有“提交、记录、受理、留言成功”提示。
- ToG 不新增任何由本次 Agent 对话生成的单条居民留言或匿名信号；需求数据仅以无原话、无 PII 的聚合标签或趋势展示。
- 控制台与网络请求中不出现 API Key；刷新或关闭本地服务后内存配置失效。
- 真模型和确定性回退都能在 90 秒内完成主场景。

## 6. 安全回退

- 资料未覆盖：明确说“在当前已核验的演示资料中暂未找到”，再给可确认的白名单科室；不补造答案。
- 紧急事项：使用固定紧急提示，不用模拟社区电话代替 110、119 或 120。
- 医疗、法律和资格判断：只提供公开办理路径，不做诊断、裁决或审批。
- 居民输入 PII：在模型调用前脱敏；洞察层不保存原话。
- 模型失败：使用同一结构化知识生成确定性回答，不把供应商错误暴露给居民。
